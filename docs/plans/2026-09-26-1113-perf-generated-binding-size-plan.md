# Generated Binding Size - Plan

## Goal

The committed YANG and MIB bindings shrink substantially and keep decoding,
diffing, and addressing the same data, so the tree is cheaper to build, lint,
race-test, and diff. The means:

- yanggen emits one Go type per distinct subtree shape, not one per schema
  path, and names it the short, package-qualified way Go code expects.
- Both generators stop repeating per node, list, table, and column the
  behavior a generic runtime helper can own.

This plan is wrong if the SNMP runtime helpers add allocations that
`src/protocol/snmp/bench/bench-gate.sh` rejects, or if static schema data has
to become init-time function calls to shrink. Either way, the affected
generator keeps that part of its code inline.

## Baseline

Measured on 2026-09-26 at `b5427421`. File bytes come from
`find <dir> -name '*.go' -print0 | xargs -0 cat | wc -c`. The per-kind split
assigns each line to its top-level declaration.

| Tree | Bytes | Files | Largest package |
| --- | --- | --- | --- |
| `generated/go/yang` | 205,604,350 | 1,137 | `cisco-iosxe/ciscoiosxenative`, 170,104,399 |
| `generated/go/mib` | 38,589,077 | 33 | `lcosmib`, 35,113,201 |

The YANG tree has 118,704 `…Schema` vars and 14,777 descriptors. Schema
literals take 94 MB, node, key, and flat-row types 62 MB, and descriptors
49 MB. Most of that is repetition:

- In `ciscoiosxenative`, 101,665 node structs have 12,885 distinct shapes
  (12.7%). Groupings instantiated under every interface type repeat a subtree:
  one storm-control subtree appears 3,948 times.
- Identifiers of 40 or more characters take 77.5 MB, because each node's name
  concatenates all of its ancestors.
- The full YANG path is written into the comments on the node type and on its
  Schema var, which comes to 51 MB.
- The per-node `Module` and `Namespace` strings take 17 MB.
- The inline JSON and XML decode closures of nested-list descriptors take
  21 MB.

In the MIB tree, the per-column `Iter` switch takes 6.6 MB at 13 to 18 lines
per column. The per-table walker methods take about 5 MB, enum `String`
switches 3.8 MB, enum consts 6.4 MB, and comments 11.9 MB.

## Decisions

- Two phases, one per generator, with no `After` edge between them. Why: yanggen
  with `src/protocol/yang`, and mibgen with `src/protocol/snmp`, share no files
  or imports, so they are separate dependency clusters.
- yanggen goes first. Why: it holds 84% of the generated bytes and has no
  allocation gate on its hot path.
- A generator emits declarations, static data, and typed glue. Behavior that
  differs only in type parameters lives in the owning runtime package as a
  generic helper, and generated code calls it. Why: `StructRowCodec`
  (`src/protocol/yang/structops.go:211-222`) already does this for top-level
  lists; the nested-list, column-decode, and walker code are the same pattern
  left inline. The rule goes into `docs/code-style.md` under Project layout.
- Schema data stays in package-level composite literals, never in per-field
  constructor calls. Why: a composite literal of constants and addresses is
  static data. A call per field would add init-time work to every binary that
  imports a generated package.
- Generated identifiers follow Go naming: the package name is part of the
  identity, so a name does not repeat the package or the ancestors a reader
  already knows (`ciscoiosxenative.StormControlLevel`, not
  `ciscoiosxenative.NativeInterfaceCellularStormControlLevel`). Why: the user
  directed it, and Effective Go's package-names section says the same
  (https://go.dev/doc/effective_go#package-names).
- Every exported generated identifier keeps a one-line doc comment. Why:
  `docs/code-style.md:45-46` requires a doc comment on every exported name,
  and generated code is exported surface like any other.
- Breaking changes to generated names, `yang.Schema`, `yang.Field`, and the
  generated walker internals are in scope, with no shim (`AGENTS.md`, Agent
  behavior).
- Full-surface generation stays. Why: `src/protocol/yang/cmd/yanggen/yanggen.yaml`
  records the decision to include every vendored module.

## Requirements

1. The behavior tests of both runtimes and both generators pass after their
   phase. Only goldens, symbol names, and assertions on the emitted text
   change. For example, `golden_roundtrip_test.go` decodes the same fixture
   XML into rows equal to today's.
2. After its phase, `generated/go/yang` is at least 50% smaller and
   `generated/go/mib` at least 30% smaller than their baseline rows. The
   phase's outcome note records the exact numbers.
3. `src/protocol/snmp/bench/bench-gate.sh` passes against the committed
   `baseline-micro.txt`, including `BenchmarkTableWalk/impl=flowseer`, and
   the baseline is not rewritten.
4. Generated code imports only the public API of its runtime package.

## Out of scope

- Pruning vendored YANG modules or MIBs.
- The protobuf tree `generated/go/proto`.
